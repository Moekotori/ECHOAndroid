# 界面交互与动效检查（2026-10-31）

本次检查 Android 页面与共享交互实现，并在现有 Android 模拟器上操作真实曲库。工作区存在大量并行改动，未提交或覆盖其他任务的修改。音频引擎、PC 端、协议与数据库不在本次修改范围内。

## 已修正

1. **退出中的页面仍有返回处理器或按钮响应。** 共享 `EchoInteractionGate` 隔离退出内容的触摸与无障碍节点；页面交互资格向下传递给普通和预测性返回处理器。队列及播放器设置内部切页也接入该边界。外层分页手势不因页面暂时失去返回资格而被截断。
2. **音乐关系页在外层翻页时闪空，曲库子页直接替换内容。** `EchoLibraryDestinations` 负责曲库、音乐关系、电台、播客之间的转场与有界状态保存；音乐关系页在外层滑动时保留画面。电台列表与详情也使用共享页面转场。
3. **从曲库子页返回会跳回列表顶部。** 保存上次查询、排序和来源，只在这三项真正改变时回顶；重建页面时保留恢复的滚动位置，筛选变化仍沿用原有保持位置的行为。
4. **统计页进入月报后丢失筛选与滚动位置。** 使用独立页面状态与可中断转场；加载状态不再销毁列表状态。相同月份刷新保留已显示的月报，首次加载或切换月份仍显示真实加载状态。
5. **连接页切换后输入焦点残留。** 点击、横滑切换及离开页面时释放旧编辑器焦点、关闭键盘；预加载的未激活页面不抢焦点。来源卡片折叠也释放输入焦点。
6. **键盘把页面整体顶入状态栏。** 主 Activity 明确使用 `adjustResize`，让 Compose 的 IME inset 处理可用空间。
7. **歌词预览隐藏后或系统关闭动画时仍运行帧循环。** 预览同时遵守页面交互资格、窗口焦点、生命周期与系统 `MotionDurationScale`；保留原有 30 fps 上限及轻量模式逻辑。
8. **覆盖页下方仍暴露无障碍控件。** 搜索、历史等覆盖页打开时隐藏主 shell 的无障碍节点；统计覆盖历史时也隐藏历史节点。

## 第二轮：动画连续性与重组范围

进一步修改集中在三个模块，未调整音频热路径、协议或资源文案：

- `:core:design`：设置页入口的分组入场只执行一次，并保存已展示状态。中途离开或再次进入，不再把已显示内容的透明度清零重播。
- `:feature:settings`：每个设置子页独立绘制不透明背景，普通模式的前进/返回同步执行位移与层级缩放，取消“旧页淡完后新页才淡入”的空档。轻量模式保留短淡变。
- `:feature:player`：歌词设置抽屉的动画高度只在测量阶段读取；保留原有高度限制和弹簧，避免高度每帧变化时重新执行整个设置页与歌词预览的组合代码。

这是对具体状态重置、串行转场和状态读取阶段的修正，没有延长整体动画时间，也没有增加常驻帧循环。状态读取阶段依据：[Compose performance best practices](https://developer.android.com/develop/ui/compose/performance/bestpractices#defer-reads)。

三个涉及模块的 Kotlin 编译和模块 lint 通过，4 个相关分组入场/回弹用例通过。模块 lint 均为 0 错误，已有建议性警告未批量处理。整包尝试受到并行开发中的 `NfcMusicDialog.kt` 缺少 `nfc_music_*` 文案资源阻挡；不修改该功能或添加占位文案来绕过构建。前节 APK 是第一轮验收包，不包含本节修改。现有模拟器的并行操作也影响了连续切页采样，本轮不把这些采样当作动画验收或性能提升证据。
