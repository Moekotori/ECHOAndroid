# PC / Android 歌词与 CUE 格式对照

2026-11-08 对照 [echosteam](https://github.com/moekotori/echosteam) 的 `a8f1bd0091db9fd103144909ff36257d6de54b2f`。
本次只修改 Android，范围是文件读取、歌词解析和曲库分轨，不涉及 PC 工作台的实体音频切割导出。

## 歌词

Android 已有 LRC / Enhanced LRC、TTML、WebVTT、YRC、QRC、KRC、SRT、ASS / SSA、TXT，另有 SPL、SBV、SAMI、JSON 等格式。

本次补齐：

| 能力 | Android 行为 |
| --- | --- |
| TRC `.trc` | 同名发现、手动导入、累计逐字时长、offset |
| SNC `.snc` | 原始 GB 编码标记、HHMMSScc 时间、续行 |
| LRCX `.lrcx` | `[tr]` 翻译、`[tt]` 字符索引逐字时间、`[ro]` 音译、`[fu]` 读音；附件标签不显示成正文 |
| AWLRC | 读取 LRC 元数据中的 base64 包装、逐字时间、翻译、音译 |
| KRC | 保留压缩读取，补 `[language]` 内嵌翻译／音译，以及无扩展名时的格式识别 |
| QRC | 同时兼容绝对／行内相对逐字时间；XML 属性可用单引号或双引号 |
| 字幕细节 | SRT 支持带小时或仅分秒的时间，排除倒序及非法分钟／秒；ASS 无 `Format:` 时使用标准字段，隐藏绘图内容，保留正文和 karaoke 时间 |
| 旁置文件 | 同目录及 `lyrics/` 下的同名、完整音频文件名（如 `song.flac.lrc`）、`.t` / `.r` 及语言后缀；找不到主文件时可提升语言文件为主歌词 |
| 翻译／音译合并 | 定时附件按 PC 的 350 ms 容差一对一匹配，纯文本附件按行匹配；CUE 片段按各来源的原时间裁剪 |
| TTML 富信息 | 按行 ID 关联外置翻译／音译，保留语言、角色 ID 和歌手名称；每行最多八份语言附件，缓存读写保留这些信息 |

新格式沿用已有歌词快照、导入缓存和 CUE 歌词裁剪流程，不增加后台轮询。
LRCX 单独保存假名读音并兼容现有音译显示；语言附件保留在共享模型和私有缓存中，现有界面继续显示首个译文／音译。
LRC、LRCX、TRC 的文件 offset 与 PC 一致：正数提前，负数延后。例如 `[00:01.25]` 配合 `[offset:250]` 得到 1 秒；用户手动调整的显示偏移仍按现有 UI 约定叠加。
文件发现同时用于播放读取和曲库歌词检查；目录枚举、附件数量和单文件字节数均有边界，不递归搜索其他子目录。

## CUE

Android 已有外置 CUE、多 FILE、INDEX 00 / 01、原始帧数、常见传统编码、FLAC 文本／二进制 CUESHEET、APEv2 内嵌 CUE，以及本地／远程曲库的虚拟分轨和有界播放。

本次补齐文本 CUE 的 `TRACK 00 AUDIO`、`MODEx/2xxx` 数据轨，以及存在文件证据时的 WAV / WAVE → 唯一 FLAC / FLA / APE / WV 别名解析。
别名在计算分轨边界前解析，音频轨和数据轨都使用同一时间线，并保留实际文件名大小写；真实存在的 WAV 文件优先，多个可替代文件保持未解析，越界路径不重定位。
数据轨仅提供 `INDEX 00` 时也可作为前一音频轨的结束边界；完全缺少边界、倒序或重复时间仍视为读取失败。大小写不同但确实独立的音频文件保持独立时间线。
仍保留完整文档校验、读取失败时保留旧分轨的行为。未改 Room schema、模块依赖或 Echo Link 协议。

主要实现位于 `:core:lyrics`、`:core:data`；歌词格式标识在 `:core:model`，显示名称在 `:feature:player`。
