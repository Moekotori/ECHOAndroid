# Echo Link 传歌

手机和电脑都需要支持本扩展的版本。PC 实现仅在官方 [moekotori/echosteam](https://github.com/moekotori/echosteam)。这与原有 Wi-Fi 网页传文件功能独立，不需要再打开 Wi-Fi 传输服务。

## 使用

1. 手机连接 PC Echo Link 后，在连接页点击「传歌」。电脑也在 Echo Link 页面打开「传歌」。
2. 手机 → 电脑：手机点击「发送手机歌曲」，从文件选择器选择音频。电脑默认保存到系统音乐目录下的 `ECHO Link`，可在电脑传歌面板更换目录。
3. 电脑 → 手机：先在手机选择接收文件夹，再在电脑面板选择这台手机并选择歌曲。
4. 接收完成后，任一端可以点击「添加到曲库」。这是文件复制，不是播放投送或收藏/歌单元数据同步。

一次最多选择 32 个音频文件，每个不超过 1 GiB。文件按原样传输，不转码，不改写源文件；同名目标使用编号另存。仅处理文件选择器选中的音频文件，不导出整个曲库、不下载网络音乐，也不把 CUE 虚拟曲目转成独立音频。

## 连接与取消

- 传输绑定本次 Echo Link 连接。断开、重连或切换 PC 都会终止旧手机会话，即使重连后地址/token 相同。
- 关闭手机传歌面板、电脑传歌面板或主动停止会取消当前会话。没有后台离线队列，不自动重发失败上传。
- 手机每 2 秒确认一次会话；网络丢失后 PC 在 10 秒心跳超时后关闭会话并中止文件流。保存完成的文件不会因取消而被删除。
- 失败/取消时清理未完成文件；文件访问权限丢失等无法清理的情况沿现有 SAF 保存器的恢复机制处理。失败后重新连接/启动，再重新选择文件。
- 手机可同时保留一个发送任务或一个接收任务，按文件串行处理；PC 每个会话最多一个上传和一个下载，最多四个会话，32 个待处理项，12 条完成记录。

## 兼容协议

所有路由都位于 `/echo-link/v1/transfers/`，复用现有 Echo Link 鉴权和 LAN 检查，拒绝浏览器 Origin/Cookie/Sec-Fetch 请求。文件请求额外携带 `X-ECHO-Link-Transfer` 会话 ID；拥有旧配对凭据不等于拥有一个仍有效的传输会话。

| 方法/路径 | 用途 |
| --- | --- |
| `POST session` | `{version:1,name,receiveReady}` 创建连接内的临时传输会话 |
| `GET session?receiveReady=0或1` | 心跳和有界传输列表 |
| `DELETE session` | 关闭会话并取消文件流 |
| `POST upload` | 原文件请求体；必须声明 Content-Length 和百分号编码的 `X-ECHO-Link-File-Name` |
| `GET file?id=…` | 读取 PC 通过本机文件选择器提供的文件；不接受文件路径 |
| `POST ack` | `{id,success}` 确认手机保存结果 |
| `POST cancel` | `{id}` 取消单个任务 |

会话限制到当前凭据和来源地址，不落盘。旧 PC 返回 404/405/501 时，手机提示更新电脑端，不改用无鉴权上传。
